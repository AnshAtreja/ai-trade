## Architecture

```text
Kite WebSocket -> existing parser/normalizer -> LatestMarketStateStore
                                              | every applied tick, not latest-wins bus
                                              v
                               LiveMinuteCandleAssembler
                                              | settled completed 1m bars only
                                              v
                               MarketFeatureEngine (9A)
                                              v
                               MarketContextEngine (9B)
                                              v
                               MarketRegimeEngine (9C)
                                              v
                               bounded latest state -> read-only API/UI
```

`LiveMarketIntelligenceService` attaches once to the existing lossless applied-tick callback. It never changes the WebSocket parser, scanner feature rules, strategy registry, paper account or order path. The latest-wins event bus cannot safely assemble bars. The completed-minute assembler is therefore an observational adapter separate from the strategy candle aggregator. It settles a bar after its end plus one second and rejects a later tick for that bar. Missing minutes remain missing. Kite quote `volume` is session-cumulative; per-minute volume is its nonnegative delta. The first minute can use its cumulative value only when observed from the official open. Mid-session startup or reconnect without a reliable baseline yields null volume, not a fabricated VWAP.

The eight versioned benchmark tokens are context-only; 25 frozen equities supply explicitly labeled **25-stock research-sample breadth**. Desired QUOTE subscriptions are idempotent and restored on reconnect. The existing NSE EQ tradability predicate still rejects `INDICES`, so a benchmark subscription cannot make an index a scanner candidate. The regime service emits factual `MARKET_REGIME_CHANGED`, `SECTOR_REGIME_CHANGED` and `QUALITY_CHANGED` callbacks only. No strategy or order consumer is registered.

## Operational CAS and session policy

The frozen Phase 8 `NSE_CAS_ELIGIBILITY_2026_V2` remains unchanged and stops at its documented end. The separate `NSE_LIVE_CASH_SESSION_V1` policy uses replaceable `DailyCasSource`. The primary operational source is now `NSE_CM_SECURITY_MII_V1`: the dated NSE Capital Market MII security master published through the [official NSE reports page](https://www.nseindia.com/all-reports), using the header-identified `ElgbltyClsgAuctnSsn` field (`0` = `NOT_ELIGIBLE`, `1` = `ELIGIBLE`). The parser requires the requested trade date, EQ series and a valid CAS flag; duplicate conflicting rows become `UNKNOWN`, and non-EQ rows are excluded. It reconciles the cash security symbol to the canonical active Phase 3 NSE EQ identity; Kite supplies identity only and NSE supplies eligibility. The previous F&O provider remains available only as an optional consistency cross-check and never overrides the CM flag. A daily snapshot binds source date, effective trading date, file name, URL, source SHA-256, schema version, parsed EQ counts, optional cross-check version/hash, content hash, fetch time, per-token status, `MATCHED`/`NOT_FOUND`/`AMBIGUOUS`/`NON_EQ`/`STALE_IDENTITY` diagnostics and disagreement symbols. It is written atomically under `apps/artifacts/phase9/live-cas/`. A valid same-day snapshot is reused; failures retry. Missing, stale, malformed or unrecognized source data and unresolved identities produce `UNKNOWN`; equity bars are not processed under a guessed close.

NSE's [CAS page](https://www.nseindia.com/static/products-services/closing-auction-session) and the CM CAS circular chain (`NSE/CMTR/73845`, `NSE/CMTR/74466`) define the operational change. The current CM reports page visibly exposes the MII security-file report family, but this environment did not obtain today's `NSE_CM_security_01102026.csv.gz` bytes or a verified resource URL through the page's download flow. Therefore `NSE_LIVE_CAS_CM_SECURITY_URL_TEMPLATE` remains unset and health stays `SOURCE_UNAVAILABLE`; no guessed direct archive URL is configured. `NSE_LIVE_CAS_FO_REPORT_URL_TEMPLATE` is retained only for an optional cross-check, not as the primary policy source. A previous-day file, Kite master membership or a synthetic test file is not current CAS truth.

The cash calendar supplies normal and special-session boundaries. A special session uses its calendar hours. An index always uses its own normal session through 15:30 on a normal CAS-era day, never the earlier equity CAS close. Unknown future calendar dates, pre-open observations and post-continuous-session observations do not enter the 9A engine.

## Availability and recovery

- Starting after 09:15 does not backfill unseen ticks. The first late bar latches 9A `DATA_GAP` for session accumulators; ATR, exact index returns and the 9C trailing-volatility median warm only with observed completed bars. Breadth coverage gates stay explicit.
- A disconnect discards open candles and cumulative-volume baselines. Reconnection skips the remainder of that minute; subsequent observations cannot disguise missing time. Desired benchmark/equity subscriptions are restored without duplicate applied ticks.
- Market, sector and instrument-context API reads require a recent frame and their upstream market/benchmark context; unavailable values return `null` context/regime with a reason. Health reports expected/desired/active subscriptions, source status, timestamps, breadth coverage, engine errors, bounded state and version identities. Its route checks the shared broker-auth state and reports `AUTH_REQUIRED` on expiry.
- Listener failures are counted/logged at a bounded rate without blocking `LatestMarketStateStore.set`. No per-tick INFO log, live-snapshot persistence, account mutation or Kite order call was added.
