## Canonical calculations

At each candle close, the engine publishes OHLC close context; session high/low and close distances; VWAP as `sum(((high+low+close)/3) * barVolume) / sum(barVolume)`; VWAP distance/above flag; a session-reset simple mean of the last 14 true ranges and ATR/close percent; gap as `(first session open - supplied previous session close) / previous close * 100`; cumulative per-bar volume; minutes since official session open; and OPEN/MID/CLOSE buckets (first/final 60 minutes). The ATR first bar uses high-low, then prior close. These formulas are `MARKET_FEATURE_DEFINITIONS_V1`, not an implicit industry default or a copy of the replay tick's average price.

Realized volatility, relative volume/strength, opening range, breadth, sector and market context are typed nullable placeholders with `NOT_APPLICABLE`. They are not calculated or claimed as implemented in 9A.

## Time, gaps and identity

Historical `timestamp` and live `MarketCandle.startTime` are **bar-open** instants. Snapshot `timestamp` is bar-open plus interval duration: a full candle is not visible before its close. `readAt` rejects earlier as-of times and uses only the caller-supplied time, never `Date.now()`. One instrument/interval progresses chronologically. A missing bar, including the opening bar, latches `DATA_GAP` for session-level/ATR features until the next session; raw current OHLC remains available. The engine never manufactures a bar. A missing previous close yields `INSUFFICIENT_HISTORY`; unavailable volume yields `NOT_APPLICABLE`, never zero. A stale as-of read nulls feature values and marks previously available fields `STALE`.

Session reset occurs on trade-date/session/version/source identity changes. The NSE resolver rejects holidays/unknown sessions and unknown post-CAS eligibility. It uses calendar special-session hours (including 2025 Muhurat) rather than replacing them with ordinary instrument-policy hours; normal post-CAS sessions use the instrument-specific earlier continuous close. Because the core engine receives a session descriptor instead of querying calendar on every bar, callers must use an authoritative resolver. General non-NSE live session resolution and full real-stream subscription are not 9A capabilities.

Snapshot ID is SHA-256 truncated to 24 hex characters over schema/definition version, instrument, interval, **close** timestamp, session and policy versions, source identity, values and quality. Replay/live mode and wall-clock telemetry are not part of identity. Snapshot/values/quality are frozen. A changed dataset/policy/value produces a new ID. No snapshot persistence was added.

The per-series retained market history is 14 true ranges, plus scalar session accumulators and the latest immutable snapshot; there is no unbounded candle array or session rescanning per update. Session-level volume and VWAP require per-bar volume. Actual Kite tick volume semantics must be checked at 9E before wiring the operational stream.

## Phase 9B calculations and quality

All 9B inputs are finalized 1m observations, visible at candle close. Four versioned horizons are 5m, 15m, 30m and 60m. A return is `(current close / exact same-session close H minutes earlier - 1) * 100`. No interpolation or nearest-time anchor is used. Relative return is the arithmetic difference in **percentage points** between returns over the same horizon. It is not RSI and not an order signal. The instrument, broad index and sector index may have different latest close instants, but each must be <= the requested timestamp and no more than 60 seconds old; the actual source close time is reported. If an anchor is absent because of a gap, the metric is `DATA_GAP`; if the history is too short, `INSUFFICIENT_HISTORY`; if the current observation is too old, `STALE`.

Index context reports latest close, previous-close session return, exact-horizon returns and distance from the **observed** session high/low. A missing opening index bar or later interval gap makes the full-session high/low distances `DATA_GAP`. Index volume is always `NOT_APPLICABLE` in V1; no official index volume is synthesized. The calendar supplies known trading-date/special-session opening evidence and rejects holiday rows, but the engine does **not** apply cash-equity CAS close to an index. Actual index-specific market hours remain unverified until real source data is available.

Breadth denominator is explicitly the frozen **25-stock sample**, not the whole NSE. Sector breadth denominator is that sample's sector subset. Advance/decline compares each latest fresh stock close with an explicit previous-session close; no missing previous close is invented. Incremental counters track advance/decline/unchanged and above-session-VWAP counts. Each snapshot reports expected/available counts and percent coverage. Price breadth requires at least 80% of expected constituents and at least two available observations; above-VWAP breadth has its **own** 80%/two-observation coverage gate. Percentages divide by available members only *after* the gate. A one-stock sector never returns a normal-looking breadth percentage. Insufficient coverage yields null percentages and `INSUFFICIENT_COVERAGE`, while factual counts remain visible.

All identities include context schema/definition version, registry identity, timestamp, source dataset/stream identity and explicit backcast policy. Market and sector snapshots are reused by reference across stock reads in the same revision/frame. The engine advances monotonically; a later index bar cannot be queried retrospectively at an earlier timestamp. A bounded state retains at most 61 one-minute return points per equity/index series, one active breadth contribution per constituent/scope and a compact expiry queue. A context read does not rescan all 25 stocks.

## Phase 9C - Implementation and evidence

Frozen definition SHA-256: `971add3bea30843302074c7abe2836fd78999be6d757d904239fb0c8fabf58c3`.

`regime-definition.ts` freezes `MARKET_REGIME_V1` in one registry and computes its SHA-256 definition hash. `regime-types.ts` defines orthogonal market/sector trend, volatility, breadth and relative states. `regime-engine.ts` consumes completed 9B `InstrumentMarketContext` snapshots in nondecreasing timestamp order. It has no broker, repository, event-bus, scanner, strategy or order dependency. It returns immutable market and sector snapshots with source-context ID and content identity. The broad-market snapshot is calculated once per context ID and reused across stock reads; sector snapshots are likewise cached per sector/current context. Nothing is persisted: deterministic recomputation is cheap and avoids a second large per-minute data store.

**Trend V1.** A direction requires a common 15m/30m index return, observed index proximity to the corresponding session extreme, and both advancing and above-VWAP breadth of the frozen sample in agreement. Up: returns at least +0.12%/+0.20%, <=0.40% from observed high, both breadth percentages >=55%. Down: returns at most -0.12%/-0.20%, <=0.40% from observed low, both breadth percentages <=45%. Range: absolute returns <=0.10%/0.16% and both breadth percentages in [40%,60%]. Anything conflicting or between thresholds is `UNCERTAIN`. Missing/stale/gapped benchmark, exact-horizon return, observed session range or inadequate sample/VWAP breadth also yields `UNCERTAIN` with an explicit quality and reason code. Index VWAP is **not** claimed: 9B index volume is unavailable, so the VWAP signal here is the 25-equity *sample* above-VWAP percentage.

**Volatility V1.** This is explicitly an absolute exact-same-session **5-minute index return activity proxy**, not ATR, official index volume or a complete realized-volatility estimator. Each unique completed index observation contributes one sample. At time T, classification compares the current absolute 5m return against the median of up to 60 *earlier* unique observations, retained across sessions. At least 20 earlier samples and a nonzero median are required. Ratio >=2 is `HIGH`; <=0.5 is `LOW`; otherwise `NORMAL`. Warm-up, missing/gapped/stale 5m return and a zero median produce `UNKNOWN`. The current observation is appended **after** classification. No future session contributes to an earlier median. The V1 baseline does not normalize by time of day; the real-data distribution is recorded below without retroactive tuning.

**Breadth and sector.** Breadth provenance is the frozen 25-stock sample (`e987d9599c8c8e8b6e39bb40` context registry), never exchange-wide breadth. The output preserves expected/available counts, coverage and quality; contradictory index/breadth evidence is `CONTRADICTING`, not a forced trend. Each sector uses the same trend/volatility rules with its registered sector index and 9B sector-sample breadth. Sector-vs-market 15m return difference >=+0.10 percentage point is `OUTPERFORMING_MARKET`, <=-0.10 is `UNDERPERFORMING_MARKET`, otherwise `INLINE_WITH_MARKET`; missing comparison is `UNKNOWN`. One-stock sectors and sectors without an exact index remain quality-gated/unavailable, not silently proxied. Evidence strength is deterministic agreement (`HIGH` for four directional groups, `MEDIUM` for range or three partial groups, `LOW` otherwise), not a probability. `anomaly` is null in V1; high volatility never becomes `EVENT_DRIVEN` without actual event evidence. No hysteresis is applied in V1; transition behavior must be observed before a separately versioned change.
